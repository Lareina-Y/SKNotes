# SKNotes

SKNotes is a small cross-platform notes application built with Expo and React Native. It demonstrates stack navigation, controlled form inputs, Redux Toolkit Query, local persistence, search, and a responsive masonry-style list.

The project is intentionally client-only: it has no backend server, remote REST/GraphQL API, authentication service, or cloud database. Notes are stored locally on the device with AsyncStorage.

## Main Features

- Create notes with a title and body
- Automatically save a new note when leaving the add screen
- Edit existing notes with automatic saving as the text changes
- Delete notes from the edit screen
- Search note titles and content in real time
- Display notes in a two-column masonry layout
- Persist notes between app launches on the same device
- Run on iOS, Android, and the web through Expo

## Tech Stack

| Area | Technology | Purpose |
| --- | --- | --- |
| Application framework | Expo 57 and React Native 0.86 | Cross-platform application runtime and UI |
| UI | React Native, React Native Paper, `twrnc` | Native components, provider, and Tailwind-style utilities |
| Navigation | React Navigation native stack | Navigation between the notes, add, and edit screens |
| State and data access | Redux Toolkit, React Redux, RTK Query | Data hooks, caching, and cache invalidation |
| Local database | AsyncStorage | Persistent key-value storage on the current device |
| IDs | `react-native-uuid` | Unique IDs for new notes |
| List layout | React Native Seoul Masonry List | Two-column notes layout |

## Architecture and Data Flow

```text
React Native screens (App.js)
        |
        | generated query and mutation hooks
        v
RTK Query service (db.js) <----> Redux store (store.js)
        |
        | JSON serialization under the "notes" key
        v
AsyncStorage on the current device
```

### Frontend

`App.js` contains the three screens and the root application component:

- `HomeScreen` reads the search text, calls `useSearchNotesQuery`, renders matching notes, and opens the add or edit screen.
- `AddNoteScreen` keeps title and content in local component state. A React Navigation `beforeRemove` listener saves a non-empty note when the user leaves the screen.
- `EditNoteScreen` receives a note through route parameters, saves changes whenever title or content changes, and exposes a delete action in the navigation header.
- `App` supplies the Redux store and navigation context, then declares the native stack routes.

### State and API Layer

`store.js` creates a Redux store and registers the reducer and middleware generated by the RTK Query service.

`db.js` defines that service with `createApi` and `fakeBaseQuery`. In this project, “API” means an internal data-access abstraction rather than a network API. Its generated React hooks expose these operations:

| Operation | Generated hook | Behavior |
| --- | --- | --- |
| Fetch | `useFetchNotesQuery` | Reads all locally stored notes |
| Search | `useSearchNotesQuery` | Reads all notes and filters title/content in memory |
| Create | `useAddNoteMutation` | Generates an ID and prepends the new note |
| Update | `useUpdateNoteMutation` | Replaces the matching note's title and content |
| Delete | `useDeleteNoteMutation` | Removes the note with the matching ID |

Mutations invalidate the `Notes` cache tag, so active note queries run again and the interface reflects the latest AsyncStorage contents.

### Backend and Database

There is no separate backend in the current architecture. AsyncStorage acts as a simple local database:

- All notes are stored as one JSON array under the key `notes`.
- Each note has the shape `{ id, title, content }`.
- Data is device-specific and is not synchronized between devices.
- Clearing the app's storage or uninstalling the app may remove the notes.
- AsyncStorage is suitable for this learning project, but a production app may use SQLite for richer local queries or a secured backend for accounts, synchronization, sharing, and backups.

## Getting Started

### Prerequisites

- Node.js 20.19.4+, 22.13.0+, or 24.3.0+ (use an even-numbered LTS release)
- npm
- For a physical device: the Expo Go app on iOS or Android
- For a simulator: Xcode/iOS Simulator on macOS or Android Studio/Android Emulator

### Install and Run

```bash
git clone https://github.com/Lareina-Y/SKNotes.git
cd SKNotes
nvm use # optional; reads the included .nvmrc when nvm is installed
npm ci
npm start
```

When the Expo development server opens, scan the QR code with Expo Go or press the displayed shortcut for an available simulator or browser.

You can also start a target directly:

```bash
npm run ios
npm run android
npm run web
```

No `.env` file, API key, backend process, or database setup is required.

## Useful React Native Concepts to Review

This codebase is a compact reference for several interview topics:

- Functional components and Hooks (`useState`, `useEffect`)
- Controlled `TextInput` components
- Rendering lists with stable keys
- Screen navigation and route parameters
- Navigation lifecycle events such as `beforeRemove`
- Local state versus global/server-style state
- RTK Query hooks, middleware, caching, tags, and invalidation
- Asynchronous persistence and JSON serialization
- Platform-independent styling in React Native

## Current Limitations

- There are no automated tests or lint scripts.
- The app has no user accounts, cloud backup, or multi-device synchronization.
- Search loads the full notes array and filters it in memory.
- Notes are stored in a single AsyncStorage value, which is not designed for complex relational data or large datasets.
- Edit auto-save writes on every title or content change and is not debounced.
- The screens and components are kept in one file; a larger app should separate screens, components, navigation, and data services.
